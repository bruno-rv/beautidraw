# 07 — Asset catalog: format, manifest schema, selection protocol

Type: grilling
Status: open
Blocked by: 03
Parent: ../map.md

## Question

Bruno's requirement: a folder of images — icons, pictures — plus a map between each file and its description, so the agent can pick the best one from the skill's own description without opening every file.

To decide:

- Asset format: SVG, PNG, or both — settled against what ticket 03 finds about how each behaves once embedded.
- Manifest format and location: one markdown table, a JSON index, or one sidecar per asset. It has to be greppable and cheap to load under progressive disclosure — a manifest that costs more tokens than it saves is a failure.
- Manifest fields: filename, description, tags/keywords, intrinsic size, dominant colour, licence, and whether the asset is tintable.
- The **selection protocol**: how the agent decides between drawing an icon from primitives and reaching for an asset. There has to be a rule, or it will do whichever it feels like and the deck will look inconsistent.
- Whether assets are recoloured to the deck palette, and whether that is even possible for the chosen format.
- How the manifest stays honest when assets are added — regenerated by a script, or hand-maintained.
